# Compiler

The NZ compiler is written in Rust: the `nz-compiler` library in the `compiler/` folder, and the `nzc` command in the `nzc/` folder. Both are one Cargo workspace at the repository root.

## Stages

| Stage | Content | Status |
|---|---|---|
| 1 | Lexer and parser (C# syntax with `package`, `import`, visibility from the name) | done |
| 2 | Semantic analysis: symbols, types, `import`, `null` and `T?` | done |
| 3 | Code generation: C backend with `clang` (`nzc build` and `nzc run`); LLVM later. Owned objects are freed in stage 4 | done |
| 4 | Ownership and borrow checker, deterministic release (owned objects are freed when they leave scope; strings are reference-counted and freed with their last holder) | done |
| 5 | Core standard library and `no_runtime` mode | `no_runtime`: a first mode (`--no-runtime`, B8); the standard library not yet |

## Packages and the loader

One folder is one package. `nzc check|build|run` accept a file or a folder, and `loader::load` turns it into a `Program`:

1. **A folder** is the entry package. Its name is the folder name; when the `package` line has dots and the folder path ends with that name (`src/app/cli` with `package app.cli;`), the name is that dotted name. The folder name must be an ASCII identifier, not a reserved word, without dots, and its first segment must not be `std`.
2. **A file** is an entry package on its own. Its name is taken from the `package` line. Other files in its folder are not read, unless the program imports the package of the file itself (`package app;` in `app/main.nz` with `import app.Helper;`): that import reads all the other `.nz` files in the folder as part of the package, so a broken sibling file fails the build.
3. **The source root**: the folder above the entry folder, or the path before the dotted name. `import a.b.C;` loads the folder `<root>/a/b`. The `std` package and built-in packages are not loaded from a folder.
4. Packages are loaded breadth-first: the entry package first, then the imported packages in import order; the files of one package are read in file name order (Unicode string order). A package that was already seen is not loaded again, so a cycle does not make the loader spin; the checker reports cycles (`sema/packages.rs`), one error per group of packages that import each other.
5. A `package` line that differs from the package name becomes a warning in folder mode, and also in imported packages in file mode; the name from the folder is used.

Each file gets a start offset in the `SourceMap` and is parsed with it, so all `Span`s (items, expressions, warnings, syntax errors) are global; `render_in` turns them back into file, line and column, including related labels in other files. A file that fails to parse stays in the `SourceMap` so its errors can be shown, but contributes no items.

**Names.** Every top-level declaration has a qualified path (`geo.Point`). The symbol table and `Ty::Named` use that path, and each file has a `FileScope` that maps the short names it may use to paths: the name of its own package (all files), explicit imports and aliases, then globs (lowest rank; two globs with one name are ambiguous only where the name is used). The C name is made from the declaration **key**: the number of segments, then each segment with its length (`app.util.Add` becomes `3_3app4util3Add`), then the argument types for a generic instance. The key starts with a non-zero digit and no key is a prefix of another key, so two packages may declare the same name. A generic instance is made once for the whole program. The table of C name prefixes is in `codegen/names.rs`.

The entry point is `<entry package>.Main`: a folder without `Main` is an error for `check`, `build` and `run`.

Warnings are a channel separate from errors. A warning is printed as `Warning:`, followed by one summary line per call that names the path as the user typed it; a warning does not change the exit code, and becomes an error only with `-Werror` (for `check`, `build`, `run` and `test`). The exit codes of `nzc`: 0 success, 1 there are errors, 2 wrong command. The warnings so far: `private` on a name that starts with a capital letter; a `package` line that differs from the folder; an `import` of a package from the file itself; a `///` documentation comment that is not attached to a declaration; a local function name that starts with a capital letter; and an unknown attribute name. After a syntax error or a loader error, `check` prints the errors and a summary line, while `build` and `run` print the errors only, with no summary line; when the loader reads no file at all, the message is `nzc: <message>` with no summary.

The block marker `nz warning="text"` means a whole program that must pass `check` without errors and produce a warning that contains `text`.

## Literals and interpolation

**Lexer.** `number()` reads one literal to its end: the prefix `0x` or `0b` (upper or lower case), digits with the `_` separator (only between two digits of the base), a fraction, an exponent, then a suffix. The result is `Int(IntLit)` or `Float(FloatLit)` (`literal.rs`). A letter or digit that sticks to a literal and is not a suffix is an error on that literal, not the start of a name: `12abc` and `0x1G` fail in the lexer. The integer value is built with `u64::checked_mul` and `checked_add`; the range is checked by suffix (without a suffix or with `L` it must fit `long`, `U` must fit `uint`, only `UL` goes up to `u64::MAX`). The `F` text is parsed straight to `f32` (rounded once) and then stored as `f64`.

**One escape table.** `lexer::decode_escape` parses `\n \t \r \0 \\ \" \'` and `\u{h...}` (1 to 6 hexadecimal digits, a Unicode scalar value). `string()`, `char_literal()` and the plain text in an interpolated string use it, so `$"\q"` gives the error `unknown escape sequence`, the same as `"\q"`.

**Raw strings.** `"""` opens a raw string that ends at the next `"""`. `raw_value` works on line ranges of the original text (so `Span` stays an original offset): `\r\n` becomes `\n`; when the closing `"""` stands alone on its line, that line gives the indentation width that is removed from every content line; a single line is not trimmed. The resulting token is still `Str`, so a raw string can be used wherever a string can, also inside an interpolation hole. `$"""` is an error ("not supported yet").

**One hole scanner.** `Lexer::skip_hole` moves from `{` to its closing `}` while reading strings, raw strings, chars and nested interpolated strings as one whole token, so a `{`, `}`, `"` or `:` inside them means nothing. `interpolated()` and `parse_interp` (through `lexer::hole_end`) use the same scanner, so the lexer and the parser cannot disagree about where a hole ends.

**Format.** `parse_hole` lexes the content of the hole and cuts it at the first `:` token outside parentheses (`hole_tokens`); the text after it, as it is, is read by `format_spec` into `FormatSpec { kind, precision, span }` (`FormatKind`: `Fixed`, `Decimal`, `Hex { upper }`; precision 0 to 99). An `InterpPart::Format` part always comes right after the `Expr` part it formats; every analysis that runs with `if let InterpPart::Expr(e)` still sees every hole. A `?` outside parentheses before the format colon is an error (`BARE_CONDITIONAL`): `{(c ? a : b)}` must be parenthesised. When a hole is nested in another interpolated string, `Module::shift_expr_spans_from` shifts the `Span` of the expression and the `Span` of every `Format` together, so both stay global.

**Checker and code generator.** `sema/literals.rs` pairs each `Format` with the `Expr` in front of it: `F` accepts all ten integer types, `float`, `double`; `D`, `X`, `x` accept all ten integer types; `char` and enums accept no format; all of this also holds for the `T?` of those types. The error points at the format text. `codegen/types.rs::formatted` calls an `nz.h` helper. The rounding of `F` is done by `snprintf("%.*f")` in the C library: the exact binary value is rounded to nearest, and ties to even (`{0.125:F2}` becomes `0.12`). This was checked on clang 22.1.8 (UCRT, Windows); the test `fixed_format_rounds_the_exact_value` will tell if another toolchain differs. NaN and infinity do not go through `%.*f` but through `nz_str_from_real`, so they print `NaN`, `Infinity`, `-Infinity`.

A `float` literal is printed as the `Debug` text of the `f32` value plus `f` (`1.5f`); a `long` literal as `INT64_C(n)`, a `ulong` literal as `UINT64_C(n)` and a `uint` as `UINT32_C(n)`; `types::c_integer_literal` writes a value of any integer type, with its minimum as `(-2147483647 - 1)` and `(-INT64_C(9223372036854775807) - 1)`.

## New operators and `defer`

**`>>>`.** The token reader takes the longest operator, so `>>>`, `>>>=`, `>>=`, `<<=`, `&=`, `|=`, `^=` and `??=` are each one token. Inside a type argument list, `expect_gt` splits `>>` and `>>>` (`List<List<List<int>>>` is closed by one `>>>` token); `>=`, `>>=` and `>>>=` are never split. The rest of a split token starts one byte further right, so an error after it underlines only itself. A `>>>` shift has the same type as `<<` and `>>`; the constant evaluator and `nz_ushr_*` use the same rule (the count is masked by the width of the type).

**Compound assignment.** One `AssignOp` per token. The checker uses `compound_applies`; the code generator uses `Emitter::apply`, which binary expressions also use, so the C result of both is the same. `bool` always evaluates both sides.

**`??=`.** The checker types `x ??= v` like `=` with a target of type `T?`; narrowing applies only to a `??=` statement inside a block and stops at the end of that block, because its value may never run. The ownership checker reads the target first (a variable that was already moved is "use of moved value") and evaluates the value inside `maybe_runs`.

**`defer`.** A `defer` runs when the block that contains it ends. So the checker withdraws the narrowing of names written by the block's `defer` at the end of the block (`end_block_defers`), also when `??=` narrows them again in between; inside the block after the `defer` statement, the name stays narrowed because the code has not run yet. The body of a `defer` must not be a `defer` without curly braces (`reject_unbraced_defer`); in the code generator `run_deferred` opens a new `defer` frame for the deferred statement, so a `defer` inside it runs when that statement finishes. A `return`, `break` or `continue` that leaves the deferred statement is rejected by the checker ("not supported yet").

## Local functions

**Parser.** The statement start scanner (`classify_statement`, `StmtStart::LocalFunction`) has told a function head from an expression since B0; `parse_local_func` now creates `Stmt::LocalFunc(Box<FuncDecl>)`. A visibility keyword in front is an error, a name that starts with a capital letter becomes a warning, and a body `=> expr;` is read by the same `parse_func_body` as top-level functions (B2a).

**Hoisting.** When the checker enters a block, all local functions that are directly in that block are declared first (`hoist_local_funcs`), so a call can come before its declaration. The signature is computed once per statement and stored per `StmtId`. Local functions and variables share one block namespace (an "already declared" error in either order). A local function that is not directly in a block (the body of an `if` without curly braces, a `for` initializer, ...) and a generic local function are rejected where they stand.

**Function boundary and captures.** The body of a local function is checked at its declaration as a function of its own (`FunctionContext`): `return` leaves the local function, `break` and `continue` do not reach loops outside it, and the `T?` narrowing of the outer function does not apply. The scope is marked with `push_boundary`; reading a variable declared beyond the boundary records a `Capture` (its identity is `ownership::Local`, not the name) for every local function whose boundary is crossed, and `this` is recorded when the body uses `this`, a field, a property or a method of its owner. The set is closed over calls once per top-level function (`sema/capture.rs`), because every body is known by then; the comment of that module explains why checking every call once at the end is enough. A function captures only variables declared before it (a later variable is `unknown name`), and a call is valid only where every variable it captures is already declared. Because NZ has no name shadowing, wherever the function is called, the name it captured points at that same variable; the code generator relies on this fact. Captures are read-only: a write to a captured variable (`=`, `+=`, `++`, `ref`, its field or element) is rejected in `captured_write`, so no write gets through unrecorded.

**Ownership checker.** See [Ownership](Ownership.md): captures are borrowed read-only inside the body, and every call reads and lends the whole capture set.

**Code generator.** A local function carries no environment; each one becomes an ordinary C function. Captures are extra pointer parameters, after the declared parameters, in the order of the capture set (`c_<name>`; `T const*` except for structs, arrays and wrapped optionals whose address the body may take); when the function uses `this`, the `self` receiver becomes the first parameter. A call passes the address of the variable's storage at the call site (`&n_x`, an existing `ref` pointer, a pattern binding, or a capture of the calling function), so nested and recursive calls pass the same address. That address is only ever a call argument, so it cannot outlive the call, and the body never frees a capture (the caller owns it). When the generator meets a shape that the checker should have rejected, it stops with the error `codegen: ...` (a safety net) and does not produce wrong code.

## Attributes and `nzc test`

**Attributes** are compile-time data. The parser keeps them in the AST (`attrs`, with `AttrArg.is_field` for the C# `Name = value` form next to `name: value`; its hand-written `Debug` keeps the `nzc parse` output of the old forms unchanged); the compiler reads `[Test]` and the interop attributes of B8 (`StructLayout`, `FieldOffset`, `DllImport`, `UnmanagedCallersOnly`, below). `[` is read as the start of an attribute list only where a declaration or member is expected, so a `[` in an expression or type position (index, array literal, `T[]`) does not change. At the start of a statement, `[` is still an error, except a group followed by a local function head: that gets a special message (see the table above). Attributes on local functions, parameters, enum members and accessors are not supported yet.

**Checking** is in `sema/attributes.rs` and reads only the attributes written in the module. An argument that is not a literal is checked with `eval_const` (bounded), so `[Ratio(1.5 + 1.5)]` and `[Tag("a" + "b")]` are errors, while `[Limit(60 * 60)]` passes. `[return: X]` is parsed and then rejected; `[return: Test]` gives one error and produces no test.

**Test mode.** `nzc test` calls `check_program_in(..., CheckMode::Tests)`: the same as the ordinary check, except for the entry point rule. The code generator then uses `generate_tests`, not `generate`: the roots are the tests in the entry package, the C `main` picks one test from `argv[1]`, and there is no `Main`. An ordinary build (`build`, `run`) uses `generate` and drops the tests and the top-level functions that are reached only from tests. Types and methods stay roots (a method used only by tests is still built).

**One process per test.** `Assert` and `Abort` end the process without releasing anything (SPEC 12), so a failing test must not stop the next test. The process is started with `NZ_ALLOC_REPORT=1`; only an exit with code 0 plus the report "nz: live owned objects = 0" and "nz: live strings = 0" means pass. The test `strings_are_counted_as_leaks` (`tests/test_runner.rs`) pins the second line down, and `tests/cli_test_command.rs` checks the whole `nzc test` report, including a leak simulated with a copy of the runtime (a safe NZ program cannot leak). The temporary folder is created by `TempBuildDir` and deleted when `nzc test` finishes, also on failure.

Limits: no filter by test name, no time limit per test (a test that does not stop hangs `nzc test`), no parallel test runs, and the temporary folder is left behind when `nzc` is killed.

## Tuples

**Types and expressions.** A tuple has two elements or more, with no upper bound. Element names are only a view over positions: `ElemNames` does not take part in comparison and `Hash`, so there is one type and one C struct. The result of `?:` uses the names of the `else` branch (a view only). Conversion between tuples is element by element through `widens_to` and only widens; how the branches of `?:` and `switch` convert (decision D9) is still open and waits for the owner.

**Statement start.** A head `(int, int) f() { ... }` inside a block is a local function (a local function head: type, name, parameters, body; a tuple is a type). `[A] (int, int) t = ...;` is still the error "expected an expression", and an attribute before a local function with a tuple type gets the local function attribute message.

**Ownership.** A tuple is `Copy` when all its elements are `Copy`; otherwise the tuple is moved whole and released whole (`drop` of each owned element, once). An element cannot be moved out, and an element assignment (`t.Item1 = v;`) moves the new value in and releases the old one. The deconstruction `var (a, b) = e;` uses one claimed temporary: each name is declared from its element, and an owned element that is discarded (`_`) is released at the end of the statement.

**Visible change.** `defer var x = 1;` and `defer var (a, b) = e;` are now rejected by the parser with the B2a embedded statement rule ("a variable must be declared directly inside a block `{ ... }`", one message, the same as `if (c) var (a, b) = e;`); before, `check` let them through and `build` failed in the code generator. The guard in `codegen/scope.rs` is still there.

**Not supported yet.** `==` on tuples, a tuple in an interpolation hole, a tuple type as the variable type of `foreach` (rejected; the type in `foreach` is not matched against the collection element yet), deconstruction into existing variables, nested and typed deconstruction, `is` with a binding on an owned tuple that was just created in that place (`(new C(), 1) is (C, int) r`; rejected for now, while `t is (C, int) r` with a variable passes), and `b ? (1, 2) : null`.

## Constants, static, aliases and small statements (B2a)

**Constants** have no storage. Top-level and member constants are evaluated together in `sema/const_graph.rs` in one dependency order across types and files (a cycle = one error); a local constant in `check_const`. Every read is recorded in `Analysis::constant(id)` (also `K.N`, `sizeof`, `nameof`) and the code generator writes it as a literal (`constant_literal`; `INT32_MIN`/`INT64_MIN` for extreme values). `default` is written by `types::default_value`. A `switch` pattern named by a constant is recorded in `Analysis::pattern_constant(switch, arm)`.

**Static** is a C global: `g_<key>` for a top-level static and `G<len>_<type key>_<field>` for a static field. `nz_init_statics()` is called in `main` after `nz_init_io()` and stores the constant initializers in declaration order; other globals start at zero. `nz_drop_statics()` (only when some static owns something) is called after `Main` or after a test returns, before the live object report, and releases owned statics in reverse declaration order. `Abort` does not reach it. The call rules for owned statics are in `sema/ownership/statics.rs` (see Ownership.md).

**A labeled jump** is a C `goto` to a label after the loop (`break`) or to the continue point (`continue`), written only when some `goto` uses it (`-Wunused-label` stays on). `defer` and the drops of the scopes that are left run once before the `goto`.

**Aliases** are expanded when a `TypeRef` is resolved (checker and code generator), so `Ty` never mentions an alias.

**The lookup order for a plain name:** local (including local constants), then a member of the owning type (an instance member only in instance methods; a static member and a member constant also in static methods and field initializers), then a top-level constant or static through the file scope, then the messages "is a type" / "must be called" / "unknown name". The code generator does not derive this order again: it reads `Analysis::constant(id)` and `Analysis::static_ref(id)` first.

**A static method** has no `self` parameter; it is called as `T.M(...)` (`static_method_call`) or by a plain name from inside the type, also from a local function without a receiver (`Emitter::static_scope`).

## Integer types, casts and enums (B1b)

**Types.** The ten integer types (`sbyte` to `ulong`, `nint`, `nuint`) are variants of `Ty` of their own, always `Copy`; `Ty::is_integer`, `is_unsigned` and `const_range` answer the properties of each type. C names: `int8_t` to `uint64_t`, `intptr_t`, `uintptr_t`; the optionals are `NZOptSByte` to `NZOptNUInt`. `char` is `uint32_t` and promotes to `int` (`Ty::promotes`, `is_integral`), but is not an integer type.

**Checker.** `sema/assignable.rs` (`assignable`) decides the implicit conversion in five assignment places: widening by `Ty::widens_to` (the C# table), tuples element by element, and constants that fit (`consteval::constant_joins`, `constant_type_converts`; a `long` constant goes only to `ulong`). `sema/promote.rs`: `numeric_binary` uses `ty::promote` and `promote_one` (C# binary promotion; with no common type its error is "no integer type holds both; cast one side"), `shift_type` (only the left side is promoted, the count must widen to `int`), `type_of_unary` and `compound_assignment` (the value must be `assignable` to the target; the operation runs in the promoted result type). The operation type is recorded in `Analysis::operand_type(id)` and read by the code generator; without that record, comparing two different number types is an internal error. `sema/enums.rs` computes `EnumRepr` (underlying type, value of each member) through a `Graph` over all enums: a value may use any member of its enum (only a cycle is an error), a member of another enum only through a cast (`uncast_member_of_another_enum`), and implicit numbering takes part in cycles. `Checker::enum_binary` (`sema/expr.rs`) serves enum operators as C# does. An enum member in a constant or static initializer keeps its enum type (`consteval::constant_enum`, `consts::enum_initializer`): it can only be stored in a static of that enum type (or its optional), and to an integer type it is rejected like CS0266 ("cannot implicitly convert `Day` to `int`; write `(int)Day.Tue`"). `sema/casts.rs`: `cast_kind(from, to)` gives a `CastKind` (`Widen`, `Narrow`, `RealToInteger`, `IntegerToReal`, `RealToReal`, `CharToInteger`, `IntegerToChar`, `Identity`; enums through their underlying type), `type_of_cast` rejects optionals and checks constants ("constant `300` does not fit `byte`"); the result is in `Analysis::cast_kind`.

**`checked` and `unchecked`.** Both are keywords (`Expr::Checked`, `Stmt::Checked`). `Checker::in_overflow_context` sets a lexical flag, and `Analysis::is_unchecked(id)` records it per `+ - *`, unary `-`, compound assignment, `++`/`--` and narrowing cast. Still checked inside `unchecked`: `/` and `%`, a real to integer cast, an integer to `char` cast. A call inside uses the context of its callee.

**Depth limits.** The parser stops at 1000 levels (`MAX_PAREN_DEPTH`: parentheses, prefix operators and casts), the checker at 1200 ("code is nested too deeply to check"), and `codegen/nesting.rs` weighs the C that will be written (call 2, parenthesis 4, cast +5, curly brace 2; budget `BUDGET` = 2500): past that, `build` and `run` say "expression nested too deeply to compile", even though `check` passes, because clang itself falls over on very deep C.

**Code generator.** `codegen/ops.rs`: `narrow` (an ordinary conversion when widening, otherwise a helper by the sign of the source: from `i64`, `u64` or `f64`), `narrow_or_truncate` (inside `unchecked`: `nz_truncate_*`) and `cast`; `Emitter::convert` (`items.rs`) converts numbers, `char` and enums. `codegen/decls.rs` writes each enum as a `typedef` of its underlying C type, the members as `#define` `((E)(literal))`, `nz_enum_name_<key>(v)` (one `case` per distinct value, the first member wins; a value without a member is printed as a number), `nz_enum_<key>_from_i64/_from_u64/_from_f64` (a range check, the error "value does not fit in `E`") and, for `switch`, `codegen/switch.rs` writes patterns through `c_integer_literal`.

**Runtime.** `runtime/nz_int.h` (included by `nz_core.h`, which `nz.h` includes; not a standalone header):

| Helper | Content |
|---|---|
| `NZ_INTEGER_OPS(suffix, T, UT, MIN, BITS)` | `add sub mul neg div rem shl shr ushr` for signed types (`i32`, `i64`, `iptr`); overflow and a zero divisor stop with "integer overflow" or "division by zero"; `MIN / -1` and `MIN % -1` overflow; the shift count is masked to `BITS - 1` |
| `NZ_UNSIGNED_OPS(suffix, T, BITS)` | the same for `u32`, `u64`, `uptr`, without `neg`; `>>` and `>>>` are both logical |
| `NZ_NARROW_SIGNED`, `NZ_NARROW_UNSIGNED` | `nz_to_<t>_from_i64`, `_from_u64`, `_from_f64` for `i8 u8 i16 u16 i32 u32 i64 u64 iptr uptr`: a value outside `T` (for reals: after truncation toward zero, NaN or out of bounds) calls `nz_does_not_fit("<type>")`, "nz: value does not fit in `<type>`", exit 1 |
| `nz_to_char_from_i64`, `_u64`, `_f64` | a `char` must be a Unicode scalar value (0 to 0x10FFFF, not a surrogate) |
| `nz_to_f32_from_f64` | `double` to `float` rounds; a finite value above `FLT_MAX` stops, NaN and infinity pass |
| `NZ_BITS`, `NZ_WRAPPING` | `nz_bits_to_<t>`, `nz_wrapping_add/sub/mul/neg_<t>` and `nz_truncate_<t>(uint64_t)` for `unchecked`; computed on an unsigned type at least 32 bits wide, so there is no UB |
| `nz_str_decimal_u64`, `nz_str_fixed_u64` (`nz.h`) | `D` and `F` for unsigned values; `X` uses `uint8_t` to `uint64_t` or `uintptr_t` by the width of its type |

`tests/runtime_sanitized.rs` compiles those helpers with `-fsanitize=address,undefined,implicit-conversion,float-cast-overflow` and skips itself with a message when the sanitizer runtime is missing.

**Not supported yet.** Combined `[Flags]` names; a constant graph that reads enum members (`const int K = (int)E.A;`); members on enums (`E.A.ToString()`; the integer types already have their constants `MinValue` and `MaxValue`, such as `byte.MaxValue`); `sizeof(nint)` and `sizeof(nuint)` (decision D9); `switch` patterns over the `long` range (a `ulong` literal above `long.MaxValue` or a suffixed literal is rejected; a named `const ulong` constant works).

## Lifted operators on optionals and `char` compound assignment (as in C#)

**Checker.** `sema/lifted.rs`: a binary operator with an operand of type `T?` or `null` (other than `==`, `!=`, `??`) is checked on the value types by `value_binary` (the plain operator's rules: promotion, enums, the `checked` context), and its result becomes `R?`, or `bool` for `< > <= >=`. `T` must be a number, `char`, `bool` or an enum (`lifts`). `&&` and `||` are not lifted. A `null` next to an enum is the underlying type for `+` (`E + U`, always null), and `E - null` is refused as ambiguous, as in C#. Unary operators (`lifted_unary`), compound assignment (`lifted_compound`) and `++`/`--` lift the same way; messages from the value rules are rewritten to name the operand types as written (`bool?`). `++`/`--` on a narrowed local uses its declared type. `+` with a `string` or `string?` operand is concatenation (`is_text`) when both operands have a text form (`has_text`: a string, number, `char`, `bool`, enum or `null`, or an optional of one); a `null` operand counts as `""`. A `char` target of a compound assignment (`promote.rs`) takes a `char` value, or an integer count for a shift (C# 12.21.4: `c += 1` is NZ1261), runs in `int` and converts back, checked.

**Code generation.** `codegen/lifted.rs`: every operand is evaluated once (`once`), then `(a.has && b.has) ? some(value) : null`; the operation on the values (`binary_values`, `unary_value`, `apply`) runs only when every operand has a value. A comparison becomes `a.has && b.has && (a.value < b.value)`. `bool?` `&`/`|` use C#'s three-valued table. A `null` operand has no value (`has` is `false`). Concatenation (`concatenation`, `concatenated`) reads each optional operand once and turns a null into `""`.

## Arguments and extension methods (B2b)

The NZ code (C# style) this section describes is in `docs/README.md` section 1.12.

**Parser.** `Param` gains `default` (the default value expression), `is_this` and `is_params`; `Expr::Call` gains `arg_names` (one optional name per argument, in source order). `this in`/`this ref` (and `ref this`/`in this`) are written before the type.

**Default values.** `sema/param_defaults.rs::resolve_defaults` evaluates defaults once signatures, constants and enums are known, in the scope of the declaring file, and stores them in `FuncSig.defaults` as `InitValue` (`Value(Constant)`, `Null`, `Zero`, and for parameters only `Real(f64)`/`Char(char)` from `sema/param_literals.rs`, owner answer R2). A local function uses `local_defaults` where it is declared.

**Binding arguments.** `sema/binding.rs`: `ArgSlot { Arg(i), Default }` per parameter; `sig_binding` binds positional arguments first, then named ones; `Checker::bind_args` reports why a call does not bind (the old count message stays when no name or default is involved). The checker records `call_modes[id]` **per argument, in source order** (the mode of the parameter it binds to), so the ownership analyses that zip `args` with `param_modes` stay aligned; `arg_slots[id]` is stored only when it is not the identity (`Analysis::arg_slots`). `assigned.rs::call_has_ref_param` maps an argument to its parameter through the same binding. Codegen (`codegen/expr.rs::bound_arguments`/`placed_arguments`) lowers the arguments in source order and then places them in parameter order, filling defaults; a default for an `in` parameter passed by address is stored in a temporary.

**Extension methods.** `FuncSig.is_extension` (first parameter marked `this`; the declaration rules are in `symbols.rs`, including `this in`/`this ref` on owned types). `sema/extensions.rs`: `has_member` (a member always wins), `extension_for` (lookup through `FileScope::func_path`; the receiver's type must equal the extended type, or be the declared optional type of a narrowed variable, or a `Shared<T>`/`Arc<T>` whose payload has that type), `extension_call` (checked as a call of the function with the receiver at position 0). The receiver is never in `args`, `param_modes` or `arg_slots`; `Analysis::extension_call(id)` gives the function's path and the receiver's mode. The ownership passes (`flow`, `borrow`, `mutates`, `unsupported`) handle the receiver by its mode (`Loan.receiver`); codegen restores the receiver as argument 0 through the same `placed_arguments` (a `this ref` receiver through a handle passes the payload's address under the run-time write lend). A property passed by `ref` is refused by `check_ref_arg` (NZ1260).

## Unions, `switch` and `Result` (B4b)

**Declarations.** `Item::Union(UnionDecl { decl, cases })`: `decl` is an ordinary `TypeDecl` (name, generics, members) and `cases` the written case types, so every pass that walks class and struct members also walks union methods. The checker gives the union `TypeKind::Union` with `TypeInfo.cases` (`sema/unions.rs`: the case rules, and the check that a union does not contain itself by value, with limits on depth, NZ1297). A case converts to its union in `sema/convert.rs` (`case_match`: an identical case first, then the one case it converts to, otherwise NZ1294).

**Patterns.** Patterns live in an arena (`ast/patterns.rs`, `PatId`, `Module::pats`). For each `switch` the checker records which case each arm tests (`pattern_cases`) keyed by the switch's `ExprId` and the arm; a `switch` statement uses `switch_stmt::stmt_key(StmtId)` as its key. `sema/union_patterns.rs` types the bindings, `sema/exhaustive.rs` gives the warnings NZ1300-NZ1302, and `sema/switch_stmt.rs` checks the statement form: one declaration space for all sections, no fall-through (the reachability of C#, with constant conditions), one `default`.

**Ownership.** A union is `Copy` when every case is `Copy`, otherwise Owned. A binding borrows its case (`ownership/unsupported.rs::bind_tested`); a tested temporary is kept in a statement frame (`codegen/stmt.rs`, `holds_is_binding`) and dropped once on every way out of the statement.

**C.** `struct T_k { uint32_t tag; union { ... } as; }`, one member `k<n>` per case; `object_kind` treats it as a struct (methods receive a pointer, `this` is `(*self)`). The drop glue drops the active case only, through the drop worklist (`codegen/drop.rs`, `codegen/unions.rs`). An unmatched `switch` expression stops with `SwitchExpressionException`.

**Built-in packages written in NZ.** `prelude::NZ_PACKAGES` lists packages whose source is NZ code (C# style) in the compiler (`prelude/result.nz`: `std.result` with `Result<T, E>`, `Ok<T>`, `Err<E>`). Their unit paths start with `<builtin>/`, their names have the prelude rank in every `FileScope` (a program's own declaration hides them), and the code generator emits only what the program uses. They are added where a program is checked or built (`nzc`, `api::Compilation`, `sema::check_source`, `parser::parse_with_builtins`), not by the loader, so `nzc parse` and the loader show the program's own files. Positional `record struct` (`parser/records.rs`, `Module::record_params`) is what `Ok` and `Err` are made of: its parameters are public fields, `new R()` zero-fills them when each type has a default (`new_expr.rs::check_record_defaults`, NZ1314), and `SymbolTable::deconstruct_parts` gives `var (a, b) = r;` its parts, as it does a tuple's (checker, code generation and the semantic index share it).

## Error propagation `?` (B4d)

**Parser.** `Expr::Propagate { value }` (`parser/exprs.rs::parse_postfix`): a `?` after an expression is the operator when the next token cannot start an expression (`parser/scan.rs::can_start_expression`, the same table `is T?` uses), otherwise the conditional, whose missing `:` gets a hint (NZ0220). The unit test `can_start_expression_matches_parse_prefix` keeps the table equal to what `parse_prefix` accepts.

**Checker.** `sema/propagate.rs`: the library `Result` by its path (`prelude::RESULT_PATH`) or an optional; the function's return type comes from `FunctionContext` (`function_name` is `None` in initializers, `defer_loop_depth` marks a deferred statement). Codes NZ1640-NZ1645.

**Flow.** `sema/ownership/flow.rs::exit_function` is shared by `return` and `?`; a `?` consumes its operand, then exits on one branch (`maybe_runs`). `sema/fields_assigned.rs::leave_function` does the same for the definite assignment of fields (a `?` in a constructor itself is refused by the checker, so it matters inside its local functions).

**C.** `codegen/propagate.rs` evaluates the operand into a temporary, tests the tag (`Err` is case 2) or the optional, and on failure builds the function's result, then writes `exit_releases` (`codegen/exits.rs`) and the defers and drops of every scope, as `return` does. What an exit in the middle of an expression must release lives on stacks: `Emitter::outer_fresh` (the temporaries of the statements and branches around it), `writeback_stack` and `pin_stack` (the lends and copy-outs of the calls around it: a pending `nz_rc_unlend_write` is still a read lend there, a copy-out is not written), and `in_flight` (values a call, tuple, record or collection has taken but not stored: `hold_in_flight` after each operand, `land` once the consumer runs). `in_flight` is recorded only in routines holding a `?` (`ModuleFacts::propagates_in`), so other programs compile to the same C.

**Pointer codegen.** `-fno-strict-aliasing` is passed to every GNU-style driver (not `clang-cl`): a pointer cast lets two pointer types reach one object, which C's aliasing rule would make undefined. A `[StructLayout]` struct is written with `#pragma pack` when it has a `Pack`, and every field offset is checked with `_Static_assert(offsetof(...))`.

**`extern` calls.** A call of `[DllImport("c")] extern int puts(byte* s);` goes to `nz_ext_puts`, declared `extern int32_t nz_ext_puts(uint8_t*) __asm__("puts")`, so a declaration a C header already has cannot clash with the NZ signature; the linker resolves the C symbol. That works where C symbols have no prefix (Linux, Windows x64). A library other than `c` and `m` is named on the first line of the C, `/* nz-link: -lname */`, which `build::link_flags` reads, keeping only `-l<plain name>`; `-L` folders from the command line are passed to the C compiler as their own arguments.

**Exports and C parts.** An export keeps external linkage and its exact C name. `nzc build --emit-c-part out.h` uses `codegen::generate_c_part`: the exports and what they reach, every function `static inline __attribute__((unused))`, every parameter, receiver and constructor `self` cast to `(void)`, no statics, no `main`, no include. Type and function names carry the package path, so parts of different packages do not clash.

**`--no-runtime`.** The checker refuses what needs `nz.h`; codegen leaves classes out (none can be used) and writes no enum name function (it returns a `string`). `"..."u8` is C's own string literal cast to `uint8_t*`: static, NUL-terminated and read-only.

## Version and target

`nzc --version` (or `-V`) prints `nzc 0.0.0-dev (<commit hash> <build date>)` and exits 0. The hash and the UTC date are taken when `nzc` is built (`nzc/build.rs`; `SOURCE_DATE_EPOCH` fixes the date, and the hash is `unknown` without git). The version stays `0.0.0-dev` until Milestone 0.1; there is no release pipeline.

`compiler/src/target.rs` holds `Target`: the triple, operating system, processor family, pointer width, executable suffix, link libraries and POSIX defines of the machine the program is built for. `Target::host()` is this machine and gives the choices the build always made; `Target::parse` accepts `x86_64-unknown-linux-gnu`, `aarch64-unknown-linux-gnu`, `x86_64-pc-windows-gnu`, `x86_64-pc-windows-msvc`, `x86_64-apple-darwin` and `aarch64-apple-darwin`, and any other triple is an error. `compiler/src/build.rs` reads the `Target` and not `cfg!`. `nzc build` and `nzc check` take `--target <triple>`; only when it is given does `nzc` pass `--target=<triple>` to clang. `nzc run` and `nzc test` run the program on this machine, so they refuse a target that is not this machine. A cross link needs the target's sysroot, which `nzc` does not provide; this has been tested on Linux x86_64 only, with a stand-in C compiler that records its arguments.

The code that describes the machine that *runs* the program stays host-dependent on purpose: the exit-code text of `nzc test`, the path comparison in `nzc`, and the URI style of the language server. `sizeof(nint)` and `sizeof(nuint)` are refused ("its size depends on the target"); no check or constant folding in `sema` or `codegen` uses the width of the host pointer.

## Always up-to-date documentation

The documents in the `docs/` folder are not written once and then left alone. Two mechanisms keep them correct.

**1. The compiler checks the code blocks.** `cargo test` reads every `.md` in `docs/` and checks each code block that has the `nz` marker:

| Block marker | Meaning |
|---|---|
| `nz` | a whole program that must pass `nzc check` |
| `nz fragment` | a piece of statements; wrapped automatically in `Main` with the `std` imports |
| `nz warning="text"` | a whole program that must pass `nzc check` without errors and produce a **warning** that contains `text` |
| `nz error="text"` | a whole program that **must fail** with a message that contains `text` |
| `nz fragment error="text"` | a piece that must fail with a message that contains `text` |
| `nz output="text"` | a whole program that passes `check`, is then **built and run**; `stdout` must be exactly `text` (`\n`, `\t`, `\\`, `\"` are interpreted) and the exit code 0 |
| `nz fragment output="text"` | a piece wrapped in `Main`, then built and run by the same rules |

The `error` marker must not be used together with `output` or `warning` in one block. An `output` block needs `clang` installed when `cargo test` runs.

The block checker reads only one file, so an example made of several files is written as a `text` block and points to `examples/packages/`; that program is tested by `tests/examples.rs`.

So when the behaviour of the compiler changes, a stale example makes the test fail and points to the file and line.

**2. The `GEN` sections are written from code.** The keyword list, the operator precedence table, the list of CLI commands, and the standard library reference are taken straight from the tables inside the compiler. To update them, from the repository root:

```bash
cargo run -p nzc -- docs docs
```

`cargo test` also checks that the `GEN` sections are up to date. If they are not, the test fails and asks you to run the command above.

The generators available:

| Name | Content | Source |
|---|---|---|
| `keywords` | the keyword list | `token::KEYWORD_TABLE` |
| `precedence` | operator precedence | `parser::BINARY_OPS` |
| `cli` | the `nzc` commands | `docs::COMMANDS` |
| `std` | built-in types and their members | `sema::builtins` |
